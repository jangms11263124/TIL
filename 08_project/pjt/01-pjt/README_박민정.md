# 💡 Project: 파이썬을 활용한 API 데이터 수집

OpenWeatherMap API를 활용하여 실시간 기상 데이터를 수집하고, Python의 딕셔너리 구조를 활용해 데이터를 가공하는 프로젝트를 진행했다.

## 🚀 단계별 구현 과정 및 학습 내용

### 1. API 연결 및 초기 데이터 수집

- **학습 내용**: `requests` 라이브러리를 사용하여 외부 API에 접속하고, JSON 형식의 데이터를 Python 객체로 변환하는 과정을 학습했다.

- **어려웠던 점**: 처음에 API Key를 발급받고 활성화되는 대기 시간과 엔드포인트 URL에 파라미터를 정확히 전달하는 설정 과정이 생소했다. 공식 문서를 대조하며 `lat`, `lon`, `appid` 등 필수 파라미터의 역할을 하나씩 매칭하며 해결했다.

### 2. JSON 데이터 분석 및 키값 추출 (기능 1, 2)

- **학습 내용**: 계층 구조를 가진 JSON 데이터에서 필요한 정보만 추출하는 방법을 익혔다.

- **새로 배운 것**: `data.keys()`를 통해 최상위 키를 확인하고, `data['main']['temp']`와 같이 중첩된 딕셔너리에 접근하는 인덱싱 기법을 익혔다.

### 3. 데이터 가공 및 한글화 (기능 3)

- **학습 내용**: 기존 영문 키값들을 직관적인 한글 키값으로 매핑하여 새로운 딕셔너리를 생성하는 작업을 수행했다.

- **성장 포인트**: 단순히 데이터를 출력하는 것에 그치지 않고, 사용자가 보기 편한 형태로 데이터를 재구조화하는 로직을 고민해 보았다.

### 4. 온도 데이터 변환 및 필드 추가 (기능 4)

- **학습 내용**: 기존 딕셔너리에 없는 새로운 키를 정의하고 계산된 값을 할당하는 과정을 실습했다.

- **시행착오 및 해결 (Troubleshooting)**:
  
  - **문제**: 처음 API 호출 시 `units=metric` 옵션을 사용하여 섭씨 온도를 바로 가져오는 바람에, 켈빈 온도를 섭씨로 변환하는 로직을 구현해야 하는 4번 문제의 취지에 맞지 않게 되었다.
  
  - **해결**: API 호출 시 단위 설정을 기본값(Standard/Kelvin)으로 수정하여 다시 데이터를 호출했다. 이후 수식($Celsius = Kelvin - 273.15$)을 적용해 섭씨 데이터 필드를 직접 추가했다. 이 과정을 통해 API 옵션 설정이 결과 데이터에 미치는 영향을 확실히 이해했다.

## 🔍 어려웠던 부분 및 해결 전략

1. **딕셔너리 제어의 미숙함**
   
   - 새로운 딕셔너리를 생성하고 값을 할당하는 문법이 익숙하지 않아 데이터 가공 단계에서 어려움을 겪었다. 하지만 반복적인 할당 연습을 통해 딕셔너리의 키-값 구조를 명확히 이해하게 되었다.

2. **API 응답 단위 파악**
   
   - 단순히 결과를 빠르게 내는 것보다, 요구사항에 맞춰 데이터를 설계(켈빈 온도로 가져오기 등)하는 사전 계획의 중요성을 깨달았다. 잘못 가져온 데이터를 다시 고치는 과정에서 API 문서의 세부 옵션을 더 깊게 파고들 수 있었다.

## ✨ 느낀 점 (Reflection)

"API를 연결하여 실제 데이터를 가져오는 과정이 매우 신기했다. 특히 가져온 원본 데이터를 내가 원하는 형태(한글 키명, 계산된 온도 필드 등)로 가공하는 과정에서 Python 문법의 실용성을 느꼈다.

**실수로 섭씨 온도를 먼저 가져왔을 때 당황했지만, 다시 돌아가 API 호출 옵션을 수정하고 직접 변환 식을 구현해 본 경험**이 가장 큰 배움이 되었다. 라이브러리가 제공하는 편리한 기능에 의존하기보다, 데이터가 처리되는 원리를 코드로 직접 구현해 보면서 데이터 핸들링에 대한 자신감을 얻었다."
