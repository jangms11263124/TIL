# 장민석

이번 8번째 프로젝트는 REST API설계이다. 주제는 금융 프로젝트를 진행하였다.

 REST란 

1. HTTP URI(Uniform Resource Identifier)를 통해 자원(Resource)을 명시하고,
2. HTTP Method(POST, GET, PUT, DELETE, PATCH 등)를 통해
3. 해당 자원(URI)에 대한 CRUD Operation을 적용하는 것을 의미합니다.

REST API란 이러한 REST의 원리를 따르는 API를 의미한다. 그 중 지난주에 배운 Django와 이번주에 배운 Django REST Framework와  postman을 활용하여 프로젝트를 진행하였다.

## F801 - 데이터 수집

- 금융 감독원 금융상품통합비교공시  API 키를 발급받아 정기예금 API를 호출하여 전체 상품 목록과 옵션 데이터를 JSON형태의 데이터로 응답받아 수집하였다.

이 부분에서 많이 막혔는데 처음에는 전에 배웠던 파이썬의 dotenv를 설치하지 않아서 오류메세지를 받았다. 이 후로는 포스트맨 요청시 계속해서 500 인터넷 서버 에러가 발생하였다.

AI에게 물어봤는데도 해결이 되지 않아 코드를 통해 하나씩 확인해보았다. 처음에는 API키를 잘 호출하는지 print를 이용해서 확인해보았는데 출력은 잘 되고 있었다. 그런데 runserver를 할경우 출력 값이 두번 찍히는 것을 보고 runserver시 코드가 한번 더 실행된다는 것을 알게 되었다. 다음에는 API키가 문제없는지 확인해보려고 url에 직접 API키를 집어 넣어 확인했는데 API키는 문제가 없었다. 다음으로는 request가 잘 되는지 확인해보았는데 여기서 문제가 발생하였다. runserver시 계속해서 JSONdecorder에러가 발생하였다. 계속해서 디버깅을 해보니 홈페이지에서 JSON형식의 요청을 위한 url이 아닌 XML형식의  요청을 위한 url이었다. 그래서 다시 바꾸고 요청을 보냈는데 여전히 오류가 발생하였다. 이번에는 url 주소창에 '0'을 하나 더 넣어서 발생한 오류였다. 결국 오류를 수정하여 200코드를 받았고 JSON파일을 받아왔다.

## F802 - 데이터 조회

- 이번주에 배운 DRF의 Serializer 를 활용해 직렬화를 하여 원하는 필드의 값들을 조회할 수 있게 하고 조회해보았다.

직렬화란 "여러 시스템에서 활용하기 위해 데이터 구조나 객체 상태를 재구성할 수 있는 포맷으로 변환하는 과정"이다. DRF에서 제공해주는 serializer를 활용하여 새로운 클래스를 정의하여 'GET'방식으로 DB에서 모든 상품을 조회하게 한 후 JSON형태로 응답을 반환하게 하였다. 데이터가 여러 개이므로 수업때 배운 내용인 many=True를 설정하였다. 수업 때 배운 내용을 복습한다 생각하고 진행하여 수월하였다. 

## F803 - 데이터 입력

- 사용자가 직접 금융상품 정보를 추가 할 수 있는 API를 구현한다. POST 요청을 통해 DB에 새로운 상품을 저장하고 저장/실패 및 예외 상황에 대한 적절한 오류 메시지를 반환한다.

F802에서 만든 view함수에 'POST'방식을 추가하여 작성하였다. Postman을 활용하여 직접 key, value를 작성하여 새로운 상품을 추가해보았다. 처음에는 오류가 발생하였는데 그 오류는 DB스키마에 있던 키 밸류 쌍 하나를 입력하지 않아서 발생한 오류여서 금방 해결할 수 있었다.

## F804 - 데이터 조회

- 사용자가 특정 금융상품의 상품 코드를 입력하면, 해당 상품과 연결된 옵션 정보를 반환한다. DB 에서 외래키 관계를 기반으로 데이터를 조회하여 Serializer로 JSON형식으로 변환한다.

DepositOptionsSerializer 클래스를 새로 만든 후 url.py에 상품코드가 들어간 새로운 url를 작성하고 'GET'방식으로 새로운 view함수를 작성하였다. 이때 외래키를 기준으로 조회를 해야하므로 F801에서 만든 두번째 모델을 참고하여 view함수에서 외래키 값을 추가하였다.

Postman을 이용하여 상품코드를 바꿔가면서 데이터를 조회해보고 같은 코드를 가진 상품이 여러 개 있는 것도 있다는 것을 확인하였다.

## F805 - 데이터 분석

- 모든 금융상품 옵션 중 최고 우대금리가 가장 높은 상품을 찾아서 반환한다. 그리고 해당 옵션과 연결된 상품 정보를 함께 제공한다.

url.py에 새로운 url을 작성하고 view함수를 작성하였다. 이번에도 'GET'방식으로 작성하였으며  가장 높은 상품을 찾아야 하므로 max함수를 사용하였다.  동일 금리가 여러 개일 경우 첫번째를 가져올 수 있게 수업 때 배운 filter를 사용하였다. 이 후 해당 옵션과 연결된 상품 정보를 가져오게 하였다. 이 후 DB를 직접확인하여 실제로 최고 우대금리가 가장 높은 상품과 비교해보았는데 잘 갖고 오는 것을 확인하였다.

## F811 - 생성형 AI

- 사용자에게 적합한 금융 상품을 추천하기 위해서는 충분한 학습 데이터가 필요하지만,
  실제로 수집 가능한 데이터는 매우 제한적이므로 수집된 실제 금융 상품 데이터와 생성형 AI 를 결합하여 더미 데이터를 생성한다.

생성형 AI에게 더미 데이터를 만들어달라고 부탁하였는데 우리가 만든 모델의 필드값의 형식을 맞추지 않아 loaddata시 오류가 났다. 그래서 다시 한번 요구사항을 정확히해서 해결했고, fixtures 파일에 넣어 다른 환경에서도 DB를 바로 확인할 수 있도록 처리하였다.
