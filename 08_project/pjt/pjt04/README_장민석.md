## 구현 기능 설명

### branch를 이용한 분할 작업
- 각자 branch를 만들어서 필수 기능을 나눠서 작업하였습니다. 이 후 merge를 통해 최종 결과물을 도출하였습니다.

### 금융 자산 목록 조회 (F401)
- 외부 데이터인 `assets.json` 파일을 파이썬의 `json` 모듈로 읽어와 메인 화면에 리스트 형식으로 출력했습니다.
- 각 자산은 고유한 `id` 값을 가지고 있으며, 클릭 시 해당 자산의 상세 게시판으로 연결됩니다.

### 자산별 독립 게시판 (F403)
- 하나의 `Post` 모델을 사용하지만, `asset_id` 필드를 통해 각 자산별로 게시글이 분리되어 보이도록 필터링 기능을 구현했습니다.
- 모든 게시글 목록은 최신순(`-created_at`)으로 정렬됩니다.

### 게시글 CRUD (F404 ~ F407)
- Create: 작성자, 제목, 내용을 입력받아 DB에 저장합니다.
- Read: 작성된 글의 상세 내용을 별도 페이지에서 조회합니다.
- Update: 게시글 수정 기능을 통해 본문 내용을 업데이트합니다.
- Delete: 불필요한 게시글을 안전하게 삭제합니다.

### 예외 처리 (F408)
- 유효하지 않은 자산 ID나 존재하지 않는 게시글 번호(PK)로 접근할 경우, 서버 에러 대신 `404.html` 페이지를 응답하게 했습니다.


## 학습 내용 (Learning Points)

### 데이터 흐름의 이해 (MVT)
- **Model**: 데이터베이스 스키마를 설계하고 `makemigrations`를 통해 실제 테이블로 변환하는 과정을 익혔습니다.
- **View**: 클라이언트의 요청을 받아 JSON 데이터를 읽거나 DB에서 데이터를 쿼리(filter, get)하여 로직을 처리하는 방법을 학습했습니다.
- **Template**: 전달받은 context 데이터를 화면에 렌더링하고, URL 태그를 이용해 동적인 링크를 생성하는 법을 익혔습니다.

### git branch
- git으로 branch 생성, 이동, 삭제 및 merge를 학습하여 분할작업을 할 수 있는 토대를 익혔습니다.


## 느낀 점

- git을 이용하여 분할작업을 하는 방법을 익히는데에만 시간을 많이 사용하였습니다. 
  그리고 django기본 프로젝트 및 app을 만드는 것도 아직까지 숙달되지 않아 헷갈려 기본 준비 작업자체에 시간 소비가 커서 이후 시간이 부족하여 아쉬웠습니다.
  views, html, models의 함수를 정의하는 것이 많이 해보지 못해서 그런가 아직 익숙치 않았습니다.
  그래도 django가 매우 편리하고 django를 이용해서 웹 서버를 이렇게까지 구현할 수 있다는 것이 신기하고 놀라웠습니다.
